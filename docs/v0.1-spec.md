# v0.1 Spec — Marketplace 核心

> v0.1 范围：三类 package 的 marketplace（上传 / 详情 / 搜索 / 评分）。**无 token**。
>
> 工期：4-6 周；按 Stage（B1-B6）切分，每 Stage 一个 commit。
> 部署：单 VPS，systemd + nginx。

## B2 — 钱包登录 + 用户

### 1. 后端

实现：
- `POST /api/auth/wallet-nonce`：生成 nonce 存 Redis（TTL 5min）
- `POST /api/auth/wallet-verify`：用 `eth_account.messages.encode_defunct` + `Account.recover_message` 验签
- `POST /api/auth/setup-handle`
- `GET  /api/me`
- `GET  /api/users/{handle}`
- `PATCH /api/users/me`

JWT 签发：claims `{ sub: user_id, addr: wallet_address, exp }`。

### 2. 前端

- `/login` 页：RainbowKit Connect Wallet → 弹签名 → POST verify → 写 cookie
- `/setup-handle`：首次登录设 handle
- `/u/{handle}`：用户主页（卡片基本信息 + 暂时空的"上传作品"区）

### 3. 测试

- 单元：nonce 签发 / 复用 / 过期
- 集成：完整登录流程（用 fixture 钱包签名）
- 反例：错误签名、过期 nonce、重复使用

### 4. 验收

- 钱包连接 → 签名 → 拿到 token → 显示自己的 handle
- 二次访问免重新签名（cookie 有效）
- 修改 handle / bio 生效

## B3 — Package CRUD + 上传向导

### 1. 后端

实现：
- `POST /api/packages`：创建 + 首次发版
- `POST /api/packages/{slug}/versions`
- `POST /api/packages/{slug}/assets`（multipart）
- `GET  /api/packages/{slug}`
- `PATCH /api/packages/{slug}`

manifest 校验用 pydantic discriminated union（`Literal["skill"|"agent"|"mcp_app"]`），按 04-package-format.md 严格校验。

资产存储：
- `/opt/agentmarket/data/uploads/{slug}/{version}/{filename}`
- 暴露 URL：`/assets/{slug}/{version}/{filename}`（nginx 直出）

### 2. 前端

- `/upload`：type 选择卡
- `/upload/skill` / `/upload/agent` / `/upload/mcp_app`：表单
  - 公共字段一致
  - type-specific 字段差异化（skill 只要 .md / agent 要 system_prompt 大文本框 / mcp_app 要 mcp.json 片段编辑器）
  - 文件拖拽上传，进度条
  - zod 实时校验
  - 草稿存 localStorage（页面切换不丢）
- 提交后跳详情页

### 3. 测试

- 后端：
  - 三类 type 上传走 happy path
  - manifest schema 错误返 400
  - slug 重复返 409
  - 大文件超限返 413
- 前端：表单校验、错误展示

### 4. 验收

- 三类 type 都能上传成功，详情页正确渲染
- 同 slug 二次上传 → 走"发新版本"路径
- 资产文件能从 `/assets/...` 下载

## B4 — 发现：列表 / 详情 / 搜索 / 排行

### 1. 后端

实现：
- `GET /api/packages?type=&q=&tag=&sort=&cursor=`
  - sort = trending / new / top_rated / most_installed
  - q 走 SQLite FTS5 索引（title + description + readme）
  - tag 走 `package_tags` join
  - 用 cursor 分页（基于 (rating_avg, id) 或 (published_at, id)）
- `GET /api/tags?q=`
- `GET /api/tags/{name}`
- `GET /api/packages/{slug}`（B3 已建，补 latest_version 完整 manifest 嵌套）

trending 算法（v0.1 简版）：
```
score = rating_avg * log(install_count + 10) * recency_decay
recency_decay = exp(-days_since_published / 30)
```
缓存 60s 到 Redis。

### 2. 前端

- 首页：trending 横滚 / by type tabs / new
- 搜索页 `/search?q=`
- 标签页 `/tags/{name}`
- 详情页：tabs（Overview / Versions / Reviews / Source）、Install 按钮（B5 才接 install-receipt）
- 列表卡片组件复用

### 3. 测试

- 搜索关键词命中 title / readme
- 多 tag AND 筛选
- sort 切换
- 分页 cursor 正确

### 4. 验收

- 50+ package 种子数据下：
  - 首页 LCP < 2.5s（local + 生产模拟）
  - 搜索 "rust" 返回相关包（排序合理）
  - by type 切换瞬时
  - 详情页所有 tab 加载正常

## B5 — 评分系统 + 反刷

### 1. 后端

实现：
- `POST /api/packages/{slug}/install-receipt`：
  - 校验登录
  - INSERT OR IGNORE 到 `installs`
  - `packages.install_count++`
  - 返回 install_command + 凭证（HMAC sig）
- `POST /api/packages/{slug}/reviews`：
  - 校验 `installs` 存在
  - 校验距 install 签发 ≥ 5min（取 `installs.installed_at`）
  - 校验 rating ∈ [1,5]
  - INSERT 或 UPDATE（已存在则 update + edit_count++，最多 1 次）
  - 异步刷新 `packages.rating_avg / rating_count`
- `GET /api/packages/{slug}/reviews?sort=&cursor=`
- `DELETE /api/packages/{slug}/reviews/me`

限流：
- install-receipt：30/h/user
- reviews POST：10/h/user

### 2. 前端

- 详情页 Install 按钮：
  - 点击 → POST install-receipt → 弹 modal 显示 install_command（含一键复制）+ 简短说明
  - install 成功后按钮变 "Installed ✓ Write a review"
- 评分 UI：1-5 星 + markdown textarea
- 评论列表：评分柱状图 + 倒序列表

### 3. 测试

- happy path：装 → 等 5 分钟 → 评（可用 `freezegun` mock 时间）
- 反例：
  - 未装直接评 → 403
  - 装了立即评 → 429
  - 同包评第二次 → 走 update，第三次 → 拒
  - rating 越界 → 400
  - 未登录 → 401

### 4. 验收

- 评分流程完整
- 反刷三层都生效
- rating_avg 显示正确并实时刷新
